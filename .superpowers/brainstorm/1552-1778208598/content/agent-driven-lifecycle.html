Agent 主动驱动的需求生命周期

这是不是你想要的流程？

1
用户在项目内点「新建需求」
填写：标题（自起的名字） + 一段简短描述。不需要写完整 spec。可以先选/不选 codebase（agent 自己也能识别）。
标题：登录历史记录
描述：想给用户加个最近登录历史的列表，让他能看到来源 IP 和时间
状态: drafting
2
agent 主动读代码做调查
不需要用户解释 — agent 拿到 codebase 路径后自己 grep / 读关键文件 / 看现有数据模型 / 看路由结构。这一步对用户是黑盒（但日志可看）。
🔍 找到 LoginViewController.swift
🔍 找到 auth/login 路由 (gateway/routes.ts)
🔍 没找到现有 history 表
状态: investigating
3
agent 有疑问 → 主动提问 ⇄ 用户回答（可循环）
代码读完后，agent 提出还需要用户确认的事情。用户在需求详情页看到提问，回复后 agent 继续整合 / 接着问。
🤖 我在两端都没找到 login_history 表，需要从 0 设计：
① 保留多少天？
② 是否记录失败登录尝试？
③ 历史列表只在 iOS 显示，还是 web 也要？
状态: clarifying
4
agent 输出完整 spec → 等用户审核确认
疑问回完后 agent 整合成完整规约（含调查发现、设计方案、变更范围、验收标准）。用户看完后 ✓ 确认 / ✗ 反驳（agent 修后再呈现）。
📄 完整规约
## 调查发现 ...
## 设计方案 ...
## 变更范围（涉及 codebase: ClawMo-iOS, gateway） ...
## 验收标准 ...
✓ 采纳并入队 ✗ 驳回 + 写理由
状态: awaiting_approval
5
autopilot 自动执行后续阶段（develop → code_review → submit_pr）
用户点 ✓ 后整个 task 接力跑。不再需要每个阶段中断等人。
状态: running
6
PR 提出 → GitHub review → 自动 fix_revision → merged
现状已有的 pr-poller 闭环不变；项目主页"待审核"区会显眼提示。
状态: awaiting_review → done

跟现状的关键差别

新流程（agent 主动）

  • 用户起手成本最低 — 一句话就够
  • agent 看完真实代码再给方案，不会瞎猜
  • spec 审核是天然 gate，避免方向错跑下去
  • 提问发生在调查之后，问得到点子上

现状（chat agent 被动追问）

  • agent 不读代码，只凭用户描述
  • 多轮问答都是表面的：保留多久、要不要 X 等
  • 真正的代码冲突 / 实现可行性要等 design 阶段才暴露
  • 没有"等用户审 spec 才执行"这个 gate
