A

spec 审核（入队前）

chat agent 写完 spec 后，需求落到「待我审核」清单，我点确认才入队。
↑ 现状已有 ready 状态，但没专门的"待办面板"展示，要去 /requirements 翻

B

plan 审核（design 阶段后）

design agent 产出 plan.md 后暂停，等我点「采纳」/「驳回（含修改意见）」再继续。
↑ 现在 design → review 走的是 reviewer agent 自动审，没人类介入。塞这里能在大量代码生成前修正方向

C

PR 评审（提 PR 后）

autopilot 提了 PR 后我去 GitHub 看，写 review 反馈触发 fix_revision。
↑ 现状已有（pr-poller 自动注入 GitHub review）。但项目主页应该把"我有待审 PR"显眼提示

D

diff 审核（提 PR 前）

develop 阶段写完代码 + agent code_review 通过后，提 PR 之前先在 autopilot 内部把 diff 给我看，我点 OK 才 push。
↑ 现在 code_review 完直接 submit_pr。塞这里能避免一些低级 PR 出去后再撤

⚠️ 多选影响

每加一个审核点 = 多一个"等用户点头"的暂停态。流程变长但更可控。autopilot 现有 Gate / ask_user 机制可以承载这些暂停点（commit 2708e4e 引入）。
全选 = 完全人在回路；只选 A + C = 现状基础上加个统一面板；只选 B = 让 plan 阶段成为关键关卡。
