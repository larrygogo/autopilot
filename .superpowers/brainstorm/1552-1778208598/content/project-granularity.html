点你心里最贴近的那一个。这决定后面 UI、DB、调度逻辑全部走向

A · 单个 git 工作目录

一个项目 = 一个 git repo。子模块在项目内部作为附加信息展示，不算独立项目。跟现在 repos 表 1:1，最直接。

B · 父仓库 + 子模块组

一个项目 = 父 repo + 全部 git 子模块。子模块不是独立项目，是项目内部的"模块"。跟现有调度组语义对齐（已实现的组级锁就是这个含义）。

N 个独立 repo 由用户挂到同一项目下

C · 用户自定义聚合

一个项目 = 用户挑选 N 个不相关 git repo 组成的工作集合（比如 ClawMo 项目下挂 iOS 端 + Gateway 后端 + 共用 SDK 三个独立仓库）。最灵活，但要新加一层 project 表，并改 requirement → project 的归属关系。
