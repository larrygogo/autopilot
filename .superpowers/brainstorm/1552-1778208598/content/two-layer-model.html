统一抽象：项目 ⊃ 代码资产 ⊃ 子模块

两层数据模型同时容纳 A/B/C — 你看这样行不行

Project（项目）= 用户的工作单位 · 提需求 / 跑任务 / 看审核 都以此为入口
Codebase（代码资产）= 物理 git 工作目录 · 是 submit_pr 和 调度锁 的真实承载
Submodule（子模块）= git submodule · 只在 codebase 内部展示，不独立成"项目"
A 场景：autopilot 自身
📁 Project: autopilot
📦 codebase: autopilot
└─ 无子模块
B 场景：含子模块
📁 Project: web-app
📦 codebase: web-app
├─ 🔗 sub: ui-kit
└─ 🔗 sub: shared
C 场景：ClawMo 全栈
📁 Project: ClawMo
📦 codebase: ClawMo-iOS
📦 codebase: gateway
└─ 🔗 sub: relay-sdk
📦 codebase: shared-types

这意味着的几个具体决定

  • 提需求：归到 project。需求里若涉及多 codebase 协同改动（C 场景），workflow 里跨 codebase 走流程
  • UI 入口：侧栏只有「项目」一个入口，进项目主页后看到所属 codebase / 需求 / 任务 / 待审核
  • 调度锁：仍然在 codebase 维度（避免同 git 仓库被多 task 改坏）。但 project 内多 codebase 可以并行
  • submit_pr：每个被改的 codebase 各自走 PR；project 维度汇总 PR 状态
  • 从 A 升到 C：随时可以给已有 project 多挂一个 codebase，无需迁移
  • "现在的 repos 表"：约等于现在的 codebase 表（保留父子模块自指），只是多了 project_id 外键
