项目主页首屏：要哪些信息块？

多选你认为打开项目第一眼应该看到的内容

①

元信息条

项目名 / 描述 / 关联 codebase 数 / 整体健康状态指示灯。必有的最小信息

②

待我审 spec

agent 调查完出了 spec 等我点 ✓ 的需求。「必要时给我审核」核心入口

③

待我回答 agent 的疑问

agent 调查后提了问题、卡在 clarifying 等我回。不答 agent 就不动

④

进行中的需求

状态 = drafting / investigating / running / fix_revision 的需求列表。看正在被 autopilot 处理的工作

⑤

进行中的 task

当前跑到 design / develop / code_review 等阶段的 task。需求颗粒太粗时这个更精细

⑥

已开 PR / 待 GitHub review

autopilot 已提到 GitHub、等我去 review 的 PR 清单（点击外链跳 GitHub）。现状的 awaiting_review 状态可视化

⑦

关联 codebase 卡片

每个挂在项目下的 codebase 一张小卡（路径、默认分支、子模块数、健康状态）。原 /repos 列表的浓缩版

⑧

最近活动时间线

最近 N 条事件：状态变化、PR 提交、agent 调查产出等。类似 GitHub repo 主页的 activity feed

⑨

「新建需求」快捷入口

顶部显眼的大按钮 / 输入框。「不断给它提需求」的核心动作不能藏

提示：选完后我会基于你选的元素画 2 种具体布局让你对比。「待我处理」类（②③⑥）通常优先级最高、放最显眼；「进行中」类（④⑤）放主区；「最近活动」（⑧）和 codebase 卡片（⑦）通常在侧边或底部。
